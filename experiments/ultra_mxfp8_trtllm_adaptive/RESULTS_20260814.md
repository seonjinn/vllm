# Nemotron 3 Ultra MXFP8 Backend Results

Date: 2026-08-14

## Setup

- vLLM: v0.27.1 with the FlashInfer TRTLLM dense MXFP8 backport
- Model: Nemotron 3 Ultra MXFP8
- Hardware: one GB200 node, four GPUs
- Parallelism: TP4, DP1, expert parallel enabled
- MoE backend: FlashInfer TRTLLM for every run
- Workloads: fixed 1K/1K, 10K/1K, and 1K/10K ISL/OSL
- Concurrency: 1, 8, and 32; ten request waves per point
- Metric: aggregate output tokens/s across four GPUs

Across the five request-complete matched points, adaptive TRTLLM improves

reported `EngineDeadError`. The SLURM allocation returned exit code zero because
the benchmark command still wrote JSON and continued, so the generated
`COMPLETE` marker does not make these rows valid.

## Conclusion

The adaptive layout improves TRTLLM throughput and prefill latency at larger
M, but it is not ready to replace the released v0.27.1 default. CuteDSL remains
7.8-13.9% faster than fully tuned fixed TRTLLM in this sweep. TRTLLM adaptive
also needs layout-aware autotuning and a fix for the long-prefill worker stall
before a complete nine-point comparison is valid.
