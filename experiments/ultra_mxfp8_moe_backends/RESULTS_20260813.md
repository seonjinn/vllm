# vLLM 0.27.1 Nemotron 3 Ultra MXFP8 MoE Results

## Result

`flashinfer_trtllm` was the fastest supported backend at every tested
concurrency. The `auto` selector chose the same backend and stayed within 0.6%
of the explicit result. Across C1, C8, and C32, explicit FlashInfer TRT-LLM had
30.2% higher geometric-mean output throughput than Humming and 21.0% higher
than Marlin.

| MoE backend | Execution path | C1 output tok/s | C8 output tok/s | C32 output tok/s |
| --- | --- | ---: | ---: | ---: |
| `auto` | selected FlashInfer TRT-LLM W8A8 | 106.75 | 540.35 | 1318.46 |
| `flashinfer_trtllm` | native MXFP8 W8A8 | 107.09 | 540.52 | 1311.00 |
| `humming` | MXFP8 weight, unquantized activation | 88.64 | 387.06 | 1003.12 |
| `marlin` | W8A16 fallback | 87.74 | 450.10 | 1083.41 |

Every measured row completed all requests with the exact expected output-token
count and no request errors. Full metrics are in `results_20260813.csv`.

## Setup

- vLLM: 0.27.1, immutable arm64 container
- GPU: one node with 4 GB200 GPUs
- Model: Nemotron 3 Ultra ModelOpt MXFP8 checkpoint
- Topology: TP4, DP1, expert parallel enabled
- Workload: random 1000 input and 1000 output tokens
- Concurrency: 1, 8, and 32; ten request waves per point
- Dense linear backend: `auto`, resolved to FlashInfer CuteDSL MXFP8
- KV cache: `auto`; chunked prefill and prefix caching enabled
- Custom all-reduce: disabled because the default path failed CUDA graph setup

Completed jobs: `2688601` (`auto`), `2688602` (`flashinfer_trtllm`), `2688603`
(`humming`), and `2688604` (`marlin`).

## Capability checks

- `deep_gemm` rejected Ultra's non-gated MoE: `kernel does not support no
  act_and_mul MLP layer`.
- `triton` rejected the GB200 CUDA device: `kernel does not support current
  device cuda`. The v0.27.1 native Triton MXFP8 MoE path targets ROCm.
- `humming` can quantize activations when
  `VLLM_HUMMING_INPUT_QUANT_CONFIG` is supplied. The row above intentionally
  records the v0.27.1 default for an explicit `--moe-backend humming` launch.
- `marlin` is a valid fallback measurement, but it is not native MXFP8 W8A8.

The first launch attempt also exposed a backend-independent GB200 failure in
vLLM custom all-reduce during CUDA graph setup. Adding
`--disable-custom-all-reduce` fixed startup for all four supported candidates.
